FROG RELIABILITY FIX V20

Cause of the intermittent bug:
- after FIRE ended, the frog stayed in the CSS class 'is-fading' for 1.1 s
- during that interval the controller already marked the frog as not playing
- if the user clicked again quickly, a new FIRE could start while 'is-fading' was still active
- the previous hide timer could then add 'is-disabled' in the middle of the new animation
- result: sometimes the button reacted but the frog looked like it did not start

Fix:
- cancel previous fade timer before every replay
- remove both 'is-fading' and 'is-disabled' before starting
- queue a click if the Spine iframe is still loading
- force the frog stage visible before sending play
- reset Spine track before replaying FIRE
- keep the existing smooth fade after FIRE

CROC V19 and fixed Private Archive behavior remain unchanged.
