V4 CLEAN REBUILD

The old fly module was removed and rebuilt.

Root cause found:
The previous fly element lived INSIDE the sticky top header, which uses backdrop-filter.
That can create a containing block for fixed descendants. On top of that, several old
CSS rules with !important were layered over each other. The fly therefore appeared to
stay attached to the same top area instead of moving across the viewport.

V4 fix:
- Fly overlay is now a direct BODY child, outside the sticky header.
- New unique class names are used.
- Movement is controlled only by one requestAnimationFrame loop.
- Position is applied only through transform: translate3d().
- It begins moving immediately, even before the Spine iframe reports ready.
- New local preview uses port 8014 to avoid seeing a cached old version.
